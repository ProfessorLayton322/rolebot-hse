# Настройка сообщества VK для LARP-бота

Эта инструкция предназначена для администратора сообщества VK. Она описывает только действия на стороне VK: что включить, какие значения получить, что сгенерировать самостоятельно и что передать ответственному за развёртывание.

Для настройки используйте полную веб-версию VK под учётной записью администратора сообщества.

## Что потребуется

Для развёртывания нужно подготовить пять значений:

| Имя | Откуда берётся | Секретное |
|---|---|---|
| `VK_GROUP_ID` | Числовой ID сообщества VK | Условно да |
| `VK_ACCESS_TOKEN` | Ключ доступа сообщества | Да |
| `VK_CALLBACK_SECRET` | Генерируется самостоятельно | Да |
| `VK_CONFIRMATION_STRING` | Показывается в настройках Callback API | Да |
| `VK_ADMIN_IDS` | Числовые ID личных страниц администраторов бота | Условно да |

Все пять значений добавляются в GitHub environment `production`. В `production-plan` они не нужны.

## 1. Включить сообщения сообщества

1. Откройте нужное сообщество VK.
2. Нажмите **Управление**.
3. Откройте раздел **Сообщения**.
4. Включите **Сообщения сообщества**.
5. Проверьте, что на странице сообщества появилась кнопка отправки сообщения.

Без этого пользователи не смогут писать боту, а бот не сможет отвечать через `messages.send`.

## 2. Получить `VK_GROUP_ID`

Найдите числовой ID сообщества в разделе управления или в адресе страницы.

Если адрес выглядит так:

```text
https://vk.com/club123456789
```

то нужное значение:

```text
VK_GROUP_ID=123456789
```

Требования к значению:

- только цифры;
- без `club`;
- без начального минуса;
- без URL и кавычек.

Если у сообщества короткий буквенный адрес, числовой ID можно найти в основной информации в разделе **Управление**.

## 3. Создать `VK_ACCESS_TOKEN`

Перейдите в:

**Управление → Дополнительно → Работа с API → Ключи доступа**

Затем:

1. Нажмите **Создать ключ**.
2. Укажите понятное название, например `rolebot-production`.
3. Разрешите доступ к **сообщениям сообщества**.
4. Не выдавайте доступ к стене, фотографиям, документам или рекламе: этот бот их не использует.
5. Нажмите **Создать** и подтвердите действие, если VK запросит пароль или код.
6. Скопируйте созданный ключ. Обычно он начинается с `vk1.a.`.

Скопированное значение — это:

```text
VK_ACCESS_TOKEN=<ключ доступа сообщества>
```

Это не сервисный ключ приложения и не пользовательский токен. Нужен именно ключ, созданный внутри настроек сообщества.

Никому не отправляйте токен в обычном чате, письме или задаче. Если токен оказался в публичном месте, удалите его в VK, создайте новый и замените секрет в системе развёртывания.

## 4. Подготовить `VK_ADMIN_IDS`

Определите числовые ID личных страниц пользователей, которым разрешено администрировать игры через VK.

Если адрес личной страницы администратора выглядит так:

```text
https://vk.com/id87654321
```

его числовой ID — `87654321`.

Для одного администратора значение выглядит так:

```text
VK_ADMIN_IDS=[87654321]
```

Для нескольких:

```text
VK_ADMIN_IDS=[87654321,12345678]
```

Это должен быть корректный JSON-массив чисел. Нельзя передавать имена пользователей, ссылки или числа в кавычках.

## 5. Сгенерировать `VK_CALLBACK_SECRET`

Этот секрет не выдаётся VK. Его нужно создать самостоятельно на доверенном компьютере:

```bash
openssl rand -hex 32
```

Результат будет строкой из 64 шестнадцатеричных символов. Сохраните её как:

```text
VK_CALLBACK_SECRET=<сгенерированная строка>
```

Одно и то же значение позднее нужно указать:

- в GitHub Secret `VK_CALLBACK_SECRET`;
- в поле **Секретный ключ** при настройке сервера Callback API в VK.

Значения должны совпадать символ в символ.

## 6. Получить `VK_CONFIRMATION_STRING`

Перейдите в:

**Управление → Дополнительно → Работа с API → Callback API**

1. Выберите версию API `5.199`.
2. Найдите подпись вида **Строка, которую должен вернуть сервер**.
3. Скопируйте показанный VK код без пробелов и кавычек.

Пример:

```text
VK_CONFIRMATION_STRING=abc12345
```

Не перепутайте два разных значения:

| Поле в VK | Значение для развёртывания |
|---|---|
| **Секретный ключ** | `VK_CALLBACK_SECRET` |
| **Строка, которую должен вернуть сервер** | `VK_CONFIRMATION_STRING` |

Если VK не показывает строку подтверждения до ввода адреса сервера, используйте временную процедуру из раздела «Первое развёртывание» ниже.

## 7. Что передать ответственному за развёртывание

Передайте следующие значения через защищённое хранилище секретов. Предпочтительный вариант — самостоятельно добавить их в GitHub:

**Repository → Settings → Environments → production → Environment secrets**

Шаблон комплекта:

```text
VK_GROUP_ID=123456789
VK_ACCESS_TOKEN=<ключ сообщества>
VK_CALLBACK_SECRET=<сгенерированный секрет>
VK_CONFIRMATION_STRING=<код подтверждения VK>
VK_ADMIN_IDS=[87654321]
```

При создании GitHub Secrets:

- имя секрета берётся слева от `=`;
- в значение вставляется только правая часть;
- внешние кавычки добавлять не нужно;
- не добавляйте эти значения в `production-plan`;
- не записывайте реальные значения в этот файл или другие файлы репозитория.

## 8. Получить адрес Callback API после развёртывания

Ответственный за развёртывание запускает GitHub Action **Deploy production**. После успешного выполнения он должен передать вам URL вида:

```text
https://<домен-api-gateway>/webhooks/vk
```

В журнале GitHub Actions он выводится в шаге **Deployment endpoints** как `VK callback`.

`VK_CALLBACK_URL` не является секретом и не должен добавляться в GitHub Secrets.

## 9. Подключить сервер Callback API

Вернитесь в:

**Управление → Дополнительно → Работа с API → Callback API**

Заполните настройки сервера:

| Поле | Значение |
|---|---|
| Версия API | `5.199` |
| Адрес | URL, полученный после развёртывания |
| Секретный ключ | Точное значение `VK_CALLBACK_SECRET` |

Нажмите **Подтвердить**.

VK отправит на указанный адрес событие `confirmation`. Сервер проверит `group_id` и секретный ключ, после чего вернёт `VK_CONFIRMATION_STRING`. В интерфейсе VK сервер должен получить статус **Подтверждён**.

## 10. Включить события

В настройках того же сервера откройте вкладку **Типы событий** и включите:

```text
Входящее сообщение
```

Техническое имя события — `message_new`. Остальные типы событий этому боту не требуются.

## Первое развёртывание, если VK не показывает строку подтверждения

Если `VK_CONFIRMATION_STRING` невозможно получить без адреса сервера:

1. Временно добавьте в GitHub environment `production` значение `VK_CONFIRMATION_STRING=temporary`.
2. Запустите **Deploy production**.
3. Получите `VK callback` URL в шаге **Deployment endpoints**.
4. Добавьте этот URL как сервер Callback API в VK.
5. Скопируйте настоящую строку, которую теперь показывает VK.
6. Замените `VK_CONFIRMATION_STRING` в GitHub на настоящее значение.
7. Повторно запустите **Deploy production**.
8. Вернитесь в VK и нажмите **Подтвердить**.
9. Включите событие **Входящее сообщение**.

## 11. Проверить работу

1. Убедитесь, что сервер Callback API имеет статус **Подтверждён**.
2. Убедитесь, что включено событие **Входящее сообщение**.
3. Отправьте сообщение сообществу от обычного пользователя.
4. Проверьте, что бот ответил.
5. Проверьте административный интерфейс с аккаунта, чей ID присутствует в `VK_ADMIN_IDS`.

Если подтверждение сервера не проходит, последовательно проверьте:

- `VK_GROUP_ID` содержит правильный числовой ID без минуса;
- секретный ключ в VK полностью совпадает с `VK_CALLBACK_SECRET`;
- строка в GitHub полностью совпадает с `VK_CONFIRMATION_STRING`;
- после изменения GitHub Secrets повторно выполнен **Deploy production**;
- URL заканчивается на `/webhooks/vk`;
- сервер доступен по HTTPS.

## Ротация и отзыв доступа

Если `VK_ACCESS_TOKEN` скомпрометирован:

1. Удалите старый ключ в разделе **Работа с API → Ключи доступа**.
2. Создайте новый ключ с доступом к сообщениям сообщества.
3. Замените `VK_ACCESS_TOKEN` в GitHub environment `production`.
4. Повторно запустите **Deploy production**.

Если скомпрометирован `VK_CALLBACK_SECRET`:

1. Сгенерируйте новый секрет командой `openssl rand -hex 32`.
2. Замените его одновременно в VK и GitHub.
3. Повторно запустите **Deploy production**.
4. Повторно подтвердите сервер Callback API, если VK этого потребует.
